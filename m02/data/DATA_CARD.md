# Data card: Giao Hang Anh Ti support messages (simulated)

Generated by `make_messages.py` (seed 42): `uv run python make_messages.py` rewrites `messages.csv` byte for byte. Every message is simulated from hand-written Vietnamese templates; no real customer wrote any of them. The rules below are public on purpose so learners can explain what a model learned and why it fails.

File: `messages.csv`, UTF-8, 300 rows, one short customer message to the support chat of Giao Hang Anh Ti (city Pho Rom Ra, the 8 districts of `lab/m01/data/DATA_CARD.md`).

Columns:
- `message_id`: M0001 to M0300.
- `text`: the message as typed by the customer.
- `intent`: the label, one of six values below.
- `template_id`: which hand-written template produced the message, for example `refund_08`. 127 templates in total.
- `has_diacritics`: False when the message was typed without Vietnamese diacritics (122 rows, all lower case).
- `has_typo`: True when a typo or chat abbreviation was injected (60 rows): one of `ko`, `dc`, `j`, `v`, `r`, `bh`, `nha`, `vs`, or one dropped or swapped letter inside a word.
- `unicode_form`: `NFC` for 288 rows, `NFD` for 12 rows with diacritics stored in decomposed form (base letter plus combining mark), as some keyboards produce. They look identical on screen but are different byte sequences.
- `split`: `train` (237 rows) or `test` (63 rows).

Intents and counts:

| intent | rows | meaning |
|---|---|---|
| order_status | 60 | where the order is now, whether it was picked up, delivered, cancelled |
| eta | 55 | when the order will arrive, how long delivery takes |
| complaint_late | 50 | the order is already late and the customer complains |
| refund | 45 | asks for money back, refund status, refund procedure |
| change_address | 45 | change delivery address, receiver, drop-off point |
| other | 45 | everything else: pricing, coverage, accounts, jobs, thanks |

Labelling rule: label by the action the customer asks for. A late order with an explicit request for money back is `refund`, not `complaint_late` ("Đơn AT... trễ quá, hủy đi và trả lại tiền cho tôi"). A question about when a late order arrives without complaint words is `eta`.

Generating rules: each template is filled with an order id `AT` plus 6 digits (same format as m01 orders, but ids are random and do not join to `orders.parquet`), a district, a place from Rule-lesson 5.5, an hour or a number of minutes. Then, independently: 45% lower-case first letter, 20% one typo or abbreviation, 40% diacritics removed and whole text lower-cased, 30% final punctuation removed. Duplicates after removing diacritics and case are dropped.

Split rule: 20% of templates of each intent (rounded) are held out, and every message from a held-out template goes to `test`. So no test message shares a template with a training message. This is stricter than a random row split: a random 80/20 split puts near-duplicates (same template, different order id) on both sides and makes accuracy look better than it is. Measured with scikit-learn defaults (TfidfVectorizer, LogisticRegression C=1) on raw text: 0.88 accuracy on a stratified random row split versus 0.62 on this template split. The m02/c01 lab baseline (normalized text, C=10) reaches 0.778 accuracy and 0.757 macro F1 on this split.

Known limits:
- Short, template-like phrasing; real chats are longer, mix several intents and contain slang this set does not cover.
- Test set is small (63 rows) and several test rows come from the same template, so one template can move accuracy by up to 8 points. Report the confusion matrix, not only accuracy.
- `other` is a catch-all with very different topics; it is the hardest class for word-count models.
- Order ids are noise for intent; models that keep them as tokens can memorise them.
