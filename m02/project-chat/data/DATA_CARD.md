# Data card: m02 project chat data (simulated)

All data is simulated. No real customer, order or message is included.

## orders.csv

Generated by `make_orders.py` (seed 15): `uv run python make_orders.py` rewrites the file byte for byte. 40 orders in progress at Giao Hang Anh Ti (city Pho Rom Ra) on 2026-11-05 at 10:30, same status mix as `m02/c11/data/live_orders.csv`: 16 out_for_delivery, 8 picked_up, 7 delivered, 6 created, 3 cancelled.

Columns: `order_id` (AT + 6 digits), `customer_id`, `created_at` (08:00 to 10:25), `status`, `district` (8 districts of `lab/m01/data/DATA_CARD.md`), `distance_km`, `items`, `weight_kg` (items x 0.9 + 0.3), `order_value_vnd`, `payment` (cod or prepaid), `service` (express or standard), `vehicle`, `shipper_exp_months`, `is_rain` (always True: it rains that morning), `delivered_at` (HH:MM, created_at + 48 minutes, delivered orders only), `note` (free text typed by the sender).

Eight fixed orders belong to the five demo customers used in lessons, tests and evals:

The other 32 orders belong to 32 random customers (C10000 to C19999) and exist so that "someone else's order" is a real row.

## eta_snapshot.json

Generated by `make_eta_snapshot.py`: trains the module 01 project model (`m01/project-eta/solution`, Ridge, test MAE 10.833 minutes, version `eta-4b6204ab52`) in a temporary folder and stores its predicted total delivery minutes for the 30 active orders. `predict_eta` returns `max(5, round(total - minutes since created_at))` at the configured clock 2026-11-05 10:30. The snapshot keeps evals stable when P1 is retrained; the running app can call P1 over HTTP instead (`ANHTI_ETA_URL`).

## Known limits

- One morning, one weather condition, 40 orders; real traffic has far more orders per customer and many more statuses.
- Notes are empty except two: a shipper instruction on AT051122 and an injection on AT052290.
